# Milestone 5 Gate — Implementation Passed

Date: 2026-07-20

## Delivered

- Live verification of commit content addresses, canonical decoding, signatures, historical epoch decryption, dependencies, orphan blobs, and typed rebuild equality.
- Typed repair builds the full candidate state before one atomic metadata replacement; CLI index repair similarly performs one transactional replacement.
- Closed-store backup acquires the writer lock, excludes volatile files, signs a
  canonical hash/size catalog with the endpoint identity, optionally includes
  the encrypted key vault, and never overwrites a destination.
- Restore validates canonical format, signature, optional expected signer,
  every hash/size, and every relative path before atomically publishing its
  destination; restored key files are reset to owner-only permissions.
- `iroh-db-cli` commands: `inspect`, `verify`, `repair-indexes`, `backup`, and
  signer-pinned `restore`. Standalone reports explicitly distinguish structural
  verification from application-registered typed replay.
- Low-cardinality apply/query latency, index, quarantine/rebase, sync, snapshot,
  repair, and durable snapshot-age metrics; structured operation spans; and
  per-stream provider/fetch counters without record or capability labels.
- An application-replaceable `KeyProvider` boundary with the encrypted
  owner-only file vault as the default.
- Application-registered adjacent schema migrations with bounded invisible
  stage commits, causal source-cut validation, atomic activation, explicit
  rebase outcomes, fork freezing, multi-domain resumption/progress reporting,
  snapshot-tail recovery, and a crash-resumable v5→v6 shadow store upgrade.
- Explicit store/wire/object versioning policy, canonical golden fixtures, MSRV 1.91, strict CI, dependency policy, release dry-run workflow, security checklist, and changelog.
- Cargo-fuzz targets for commit/body, sync/gossip, signed security objects,
  durable schema/materialized state, and merge laws across every built-in CRDT
  family. Each target has a checked-in bounded corpus replayed on CI/release;
  weekly mutation jobs retain evolved corpora and crash artifacts.
- A deterministic real-iroh repeated partition/reconnect schedule plus an opt-in extended soak controlled by exact duration or a bounded round count.
- A reusable real-iroh production testkit with bounded operation deadlines,
  explicit sync/node faults, durable peer restart, full-mesh convergence, and
  typed reports/errors. The ordinary churn lane injects two durable restarts.
- Exact-duration soak qualification via `IROH_DB_SOAK_DURATION_SECS`, with a
  bounded live keyspace, a fail-closed anonymous-RSS budget, and a
  monthly/manual self-hosted workflow that retains the complete 72-hour log.

The complete workspace gate passes and the extended soak is intentionally
ignored unless explicitly selected. The accelerated real-network churn test
performs repeated offline writes and reordered pair reconnections across three
peers, then proves identical state roots and complete records. Backup/restore
proves state-root equality and rejects a modified archive before creating a
destination. The full cargo-deny policy accepts exceptional licenses only
through reviewed package-scoped entries and accepts only three reasoned
informational upstream advisories; every unlisted finding remains fatal. On
this candidate, the optimized encrypted local-stream benchmark measured 207.5
MiB/s and the shaped encrypted multi-source benchmark sustained 24.0 MiB/s
against its 21.6 MiB/s floor on this host.

Fuzz qualification replays twenty checked-in malformed, boundary, and
structure-aware valid seeds through the same five shared harnesses used by
libFuzzer. Structured prefixes convert mutable seed suffixes into valid
canonical objects, including signed inputs that blind byte mutation is
unlikely to discover. The scheduled/manual workflow runs each target
independently with a ten-minute default mutation budget, rejects durations
outside 1 through 18,000 seconds, and retains both the evolved corpus and crash
evidence. A bounded local smoke run of every target is required for this
checkpoint; it is not represented as a long-running fuzz campaign.

Cargo verifies the workspace source through strict Clippy, tests, and docs.
The package verifier assembles every crate archive, extracts its normalized
manifest and packaged files, patches internal dependencies to the other
extracted archives, patches version-normalized Git dependencies back to their
exact resolved development sources, and compiles every packaged crate with all
targets. The separate release-source gate still rejects every Git dependency.
Publication is temporarily and intentionally blocked by
`scripts/verify-release-ready.sh`: Cargo normalizes versioned Git dependencies
to their registry versions, where the required `iroh-blobs` shutdown fix is not
yet available. After an audited crates.io release replaces the pin, the release
gate must pass before the existing `cargo publish --workspace --dry-run
--no-verify` step. The dry-run uses `--no-verify` because Cargo's built-in
verifier would instead resolve mutually unpublished internal packages from the
public registry.

## Extended Qualification

The long-duration harness is delivered but a literal 72-hour wall-clock run was not performed inside this implementation session. Release qualification must run:

```console
IROH_DB_SOAK_DURATION_SECS=259200 \
IROH_DB_SOAK_RESTART_EVERY=97 \
IROH_DB_SOAK_RECORD_SLOTS=256 \
IROH_DB_SOAK_MAX_RSS_ANON_KIB=262144 \
IROH_DB_SOAK_MIN_ROUND_MILLIS=1000 \
IROH_DB_SOAK_OPERATION_TIMEOUT_SECS=30 \
IROH_DB_SOAK_METRICS_PATH=iroh-db-soak-metrics.tsv \
  cargo test -p iroh-db-testkit --test churn extended_partition_reconnect_soak -- --ignored --nocapture
```

and retain its logs. `.github/workflows/soak.yml` encodes this gate on an
explicitly labelled self-hosted runner because GitHub-hosted jobs cannot run
for 72 hours. The runner must be dedicated for the qualification window; the
workflow retains both the test log and Linux process/host resource metrics,
including anonymous, file-backed, and shared RSS. The live record keyspace is
bounded independently from immutable commit-history growth, and anonymous RSS
above 256 MiB fails the run before host exhaustion. The one-second minimum
round duration yields approximately 259,000 rounds in 72 hours while keeping
immutable-history disk demand predictable.
This is kept explicit rather than representing an accelerated test as
elapsed-time evidence.
