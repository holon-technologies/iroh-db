Date: 2026-07-19

## Delivered

- Live verification of commit content addresses, canonical decoding, signatures, historical epoch decryption, dependencies, orphan blobs, and typed rebuild equality.
- Typed repair builds the full candidate state before one atomic metadata replacement; CLI index repair similarly performs one transactional replacement.
- Closed-store backup acquires the writer lock, excludes volatile files, checksums every selected file, optionally includes the encrypted key vault, and never overwrites a destination.
- Restore validates format, every hash/size, and every relative path before creating its destination; restored key files are reset to owner-only permissions.
- `iroh-db-cli` commands: `verify`, `repair-indexes`, `backup`, and `restore`.
- Low-cardinality operational database counters and per-stream provider/fetch counters without record or capability labels.
- Explicit store/wire/object versioning policy, canonical golden fixtures, MSRV 1.91, strict CI, dependency policy, release dry-run workflow, security checklist, and changelog.
- Cargo-fuzz targets for commit/body and sync/gossip canonical decoders.
- A deterministic real-iroh repeated partition/reconnect schedule plus an opt-in extended soak controlled by `IROH_DB_SOAK_ROUNDS`.

The complete workspace gate passes and the extended soak is intentionally
ignored unless explicitly selected. The accelerated real-network churn test
performs repeated offline writes and reordered pair reconnections across three
peers, then proves identical state roots and complete records. Backup/restore
proves state-root equality and rejects a modified archive before creating a
destination. The full cargo-deny policy accepts exceptional licenses only
through reviewed package-scoped entries and accepts only three reasoned
informational upstream advisories; every unlisted finding remains fatal. The
optimized encrypted local-stream benchmark measured 208.4 MiB/s on this host.

Cargo verifies the workspace source through strict Clippy, tests, and docs.
The package verifier assembles every crate archive, extracts its normalized
manifest and packaged files, patches internal dependencies to the other
extracted archives, and compiles every packaged crate with all targets. The
publish dry-run then uses `--no-verify` because Cargo's built-in verifier would
instead resolve mutually unpublished internal packages from the public
registry. The dry-run performs Cargo's client-side pre-upload checks but does
not exercise registry-server validation; actual publication must preserve
Cargo's dependency order.
