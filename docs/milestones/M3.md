# Milestone 3 Gate — Passed

Date: 2026-07-19

Milestone 3 replaces copied domain seeds and manual membership with durable signed domain authority.

## Delivered

- One stable iroh endpoint identity with an encrypted, owner-only, multi-domain epoch-key catalog.
- Signed canonical domain descriptors, bounded least-privilege capability chains, three consistency modes, and endpoint-specific authorization.
- Target-bound online invitations over `/iroh-db/sync/1`; encrypted offline tickets are endpoint-bound and durably one-use.
- Signed single-successor control transitions binding sequence, predecessor,
  causal cut, epoch, revocations, data writer, transferable designated
  controller and its exact successor capability, and key-distribution commitment. Controller equivocation is
  retained as immutable evidence and freezes the domain independent of receipt
  order.
- Epoch rotation retains historical keys locally, rejects post-cut old-epoch forks as `RebaseRequired`, removes revoked trust/capabilities, and changes future blob/commit/gossip derivation.
- Multi-writer, single-writer, and append-only enforcement.
- Bounded durable device groups used only as application metadata; protocol identity remains an endpoint.
- Typed projection sharing writes selected current records into one independent destination transaction and never copies source commits or causal history.

## Gate Evidence

The following passed on the exact workspace tree:

```console
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

Focused integration schedules additionally prove:

- capability delegation cannot expand permissions, epoch scope, or depth;
- modified invitations, wrong endpoint identities, wrong ticket secrets, and ticket replay fail closed;
- an online invitation is released only to the endpoint authenticated by QUIC;
- a remaining member retains epoch-zero reads and converges at epoch one;
- a revoked member cannot install the next key and its offline old-epoch commit is surfaced for explicit rebase;
- only the designated controller can rotate, an authorized transfer takes
  effect at the next transition, and a cloned controller's competing siblings
  freeze both receipt orders durably;
- one store's domains have independent records, blobs, roots, frontiers, and key files;
- single-writer and append-only violations create no commit;
- the destination projection contains only selected records, an independent commit ID, and no source dependencies.

## Security Boundary

Already downloaded plaintext cannot be revoked. Rotation protects future epochs. A targeted epoch key must be delivered only to a non-revoked endpoint; the signed control transition is safe to replicate independently. User/group labels do not authorize protocol actions. Projection is the only history-sharing primitive and creates a new destination history.
