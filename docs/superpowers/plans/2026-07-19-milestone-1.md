# Milestone 1: Embedded Database Implementation Plan

## Goal and Success

Deliver an offline-only embedded `iroh-db` from the accepted architecture: typed records, deterministic CRDTs, one-domain atomic commits, rebuildable redb materializations and indexes, subscriptions, encrypted content-addressed blobs, seekable local streaming, and snapshots. Success requires a compiling public example plus unit, property and integration evidence for reopen, atomicity, convergence, rebuild and snapshot equivalence. No endpoint or network task is opened.

## Approach and Tradeoffs

Build one thin vertical slice first, then generalize. Core durable values use explicit canonical encoders instead of deriving a Rust serialization contract. `redb` owns ACID metadata; an internal blob-store port allows fast deterministic tests and an iroh-blobs filesystem adapter. The public record trait is stabilized before its derive macro. CRDT state is explicit even when that costs space, because deterministic offline merge and future compaction matter more than early compression.

## Global Constraints

- Follow the accepted architecture and Rust 1.91 MSRV.
- `#![forbid(unsafe_code)]` and workspace Clippy warnings as errors.
- Never hold redb transactions across `.await`.
- Blob bytes become durable before metadata references them.
- Every new behavior observes a failing test first.
- Durable golden fixtures do not change without an ADR.
- Errors are typed and preserve actionable context without secret material.

## Tasks

### Task 1: Workspace and Quality Baseline

**Resources:** root `Cargo.toml`, `rust-toolchain.toml`, `.gitignore`, `.cargo/config.toml`, crate manifests and `src/lib.rs`, `docs/milestones/M0.md`
**Depends on:** accepted architecture
**Interfaces and state:** ten named crates with the dependency direction from the spec; workspace lints and shared package metadata
**Implementation:** initialize Git; scaffold all crates; keep future crates compiling with documented placeholders but no false public behavior; add formatting, Clippy and test commands; record M0 evidence
**Failure behavior:** no generated crate may hide compile failures; no networking dependency is enabled in the M1 facade
**Validation:** `cargo metadata --no-deps`, `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`

### Task 2: Canonical IDs, Schema and Codec Kernel

**Resources:** `crates/iroh-db-core/src/{id,codec,schema,record,error}.rs`, core tests and golden fixtures
**Depends on:** Task 1
**Interfaces and state:** `DomainId`, `CollectionId`, `CommitId`, `SchemaId`, `CapabilityId`, `Dot`, `VersionVector`, `SchemaDescriptor`, `FieldDescriptor`, `IrohRecord`; strict size/version errors
**Implementation:** RED golden/round-trip/rejection tests; implement fixed-size IDs and domain-separated hashes; implement canonical integer-key encoding for kernel objects with strict limits; define object-safe record encoding helpers and schema validation
**Failure behavior:** reject wrong lengths, unsupported majors, duplicate fields, oversized IDs, duplicate field IDs and incompatible schema reuse
**Validation:** focused core tests, checked-in golden bytes, proptest codec round trips and malformed-input corpus

### Task 3: CRDT Engine

**Resources:** `crates/iroh-db-core/src/crdt/*`, `operation.rs`, property tests
**Depends on:** Task 2
**Interfaces and state:** causal context, dots, `Merge`/`CrdtValue` traits, `Lww`, `OrSet`, `GrowOnlySet`, `PnCounter`, `MultiValue`, `Immutable`, `OrderedList`, record existence map
**Implementation:** one type at a time with RED semantic examples; implement causal dominance/concurrency; add merge laws and operation-permutation generators; expose canonical state encoding and typed conflicts/overflow
**Failure behavior:** reject sequence/context regressions, unknown predecessors, illegal immutable writes and counter overflow; never depend on wall time
**Validation:** unit edge cases plus commutativity, associativity, idempotency and permutation convergence properties

### Task 4: Local Security and Commit Objects

**Resources:** `iroh-db-security/src/*`, `iroh-db-core/src/commit.rs`, golden/negative tests
**Depends on:** Tasks 2–3; `security-review` skill
**Interfaces and state:** device signer port and iroh key adapter, `DomainKey`, `CommitHeader`, encrypted `CommitBody`, `CommitEnvelope`, validation result, private genesis capability
**Implementation:** RED known-vector and tamper tests; add XChaCha20-Poly1305, HKDF and zeroization; canonical header/body encoding; sign/encrypt and verify/decrypt pipeline; local private-domain bootstrap
**Failure behavior:** wrong domain/epoch/key/signature/AAD/canonical form fails closed; debug/error output redacts secrets
**Validation:** golden commit vector, every-field tamper matrix, nonce uniqueness test, wrong-key/domain tests, dependency audit

### Task 5: Durable Blob and Metadata Store

**Resources:** `iroh-db-store/src/*`, `iroh-db-blobs/src/local.rs`, store integration tests
**Depends on:** Task 4
**Interfaces and state:** `BlobStore` port, memory test store, iroh-blobs filesystem adapter, redb tables, `Store::open`, `apply_commit`, `get_record`, frontier and author sequence
**Implementation:** RED reopen/idempotency/atomicity tests; create and validate directory format; write blob before redb apply; persist accepted commit metadata, schemas, CRDT record state and primary/equality indexes in one transaction; single-writer lock; orphan scan
**Failure behavior:** duplicates are idempotent; missing blobs and schema mismatch fail; injected failures before/after blob durability never expose partial records
**Validation:** temp-directory reopen tests, fault injection, redb transaction rollback, orphan detection, no-await transaction review

### Task 6: Record Trait and Derive Macro

**Resources:** `iroh-db-core/src/record.rs`, `iroh-db-derive/src/lib.rs`, trybuild UI fixtures, facade re-exports
**Depends on:** Tasks 2–5
**Interfaces and state:** `#[derive(IrohRecord)]`, struct/field attributes, generated schema/codec/merge/index/query constants
**Implementation:** first write hand-implemented record integration test; freeze trait surface; RED trybuild fixtures for supported example and diagnostics; implement named-struct derive with id validation, stable IDs, schema and typed field constants
**Failure behavior:** reject missing/multiple IDs, duplicate numeric IDs, unsupported types/attributes, tuple/unit/generic ambiguity and non-CRDT replicated fields
**Validation:** trybuild pass/fail suite and exact public example compilation

### Task 7: Transactions, Queries and Subscriptions

**Resources:** `iroh-db/src/{db,domain,collection,transaction}.rs`, `iroh-db-query/src/*`, integration tests
**Depends on:** Tasks 5–6
**Interfaces and state:** `IrohDb::open`, default domain, `collection`, `put/get/delete`, single-domain `transaction`, typed filters/ranges/order/limit/cursors, change stream
**Implementation:** RED vertical public API test; create one commit per transaction; apply through store kernel; implement index planner with primary/equality/range scan and stable ordering; add opaque MACed cursor; publish bounded commit batches after redb commit
**Failure behavior:** cross-domain operations cannot enter a transaction; closure/commit errors apply nothing; stale/invalid cursors are typed; lagging subscribers re-query
**Validation:** one/two-record atomicity, query matrix, pagination stability, subscription batch/lag, reopen through facade

### Task 8: Encrypted Blob Import and Seekable Stream

**Resources:** `iroh-db-blobs/src/{manifest,crypto,import,stream,store}.rs`, facade blob API, integration tests
**Depends on:** Tasks 4–5
**Interfaces and state:** `BlobRef`, configurable chunking, encrypted manifest/chunks in iroh-blobs, `BlobStream: AsyncRead + AsyncSeek`
**Implementation:** RED chunk/seek/range tests; encode/authenticate manifest; independently derive/encrypt chunks; persist through iroh-blobs adapter; implement bounded lazy chunk reads and seeks; record ownership/pins
**Failure behavior:** invalid manifest/chunk hash/tag/length/index fails before unauthenticated plaintext is returned; missing chunk is typed and retryable; disk cache holds ciphertext only
**Validation:** boundary sizes, random seeks, range accounting, corruption/wrong-epoch tests, reopen and streaming before whole-file read

### Task 9: Snapshots, Rebuild and Recovery

**Resources:** `iroh-db-store/src/{snapshot,rebuild,verify}.rs`, facade snapshot API, integration/property tests
**Depends on:** Tasks 3–8
**Interfaces and state:** canonical encrypted local snapshot, state root, frontier, schema set, atomic install, derived-state rebuild
**Implementation:** RED full-replay equivalence test; serialize canonical CRDT states/frontier; encrypt/sign snapshot; stage install; rebuild redb materializations/indexes from immutable commits or snapshot+tail; verify state roots
**Failure behavior:** malformed/untrusted/incompatible snapshots do not change active state; failed rebuild preserves original database
**Validation:** full replay equals snapshot+tail, delete-derived-and-rebuild, corruption and interrupted install tests
