# Milestone 2: Distributed Sync Implementation Plan

## Goal and Success

Add asynchronous encrypted-domain reconciliation between two or more iroh endpoints without weakening the Milestone 1 local kernel. Peers exchange only bounded control frames over `/iroh-db/sync/1`; immutable commit bytes move through iroh-blobs; gossip is a lossy announcement hint. Offline concurrent writes must converge byte-for-byte after any partition/reorder/duplicate schedule, and rejected network input must not change accepted state.

## Confirmed Upstream Surface

The locked dependency set exposes `iroh::Endpoint`, `iroh::protocol::Router`, authenticated `Connection::remote_id`, bidirectional QUIC streams, `iroh_blobs::net_protocol::BlobsProtocol`, the `/iroh-bytes/4` ALPN, verified blob fetch APIs, and `iroh-gossip` 0.101.0. The sync implementation composes these surfaces; it does not add transport, discovery, relay, hash-transfer, or gossip-tree implementations.

## Constraints

- All local behavior and the M1 gate remain green.
- The remote path verifies exact blob hash, canonical form, endpoint/author binding, signature, domain, epoch, authorization, dependency closure, AEAD, schema, operation target, and CRDT merge before atomic persistence.
- redb transactions never cross `.await`.
- Control frames are definite canonical values capped at 1 MiB; sessions cap refs, dependencies, graph depth, and total bytes.
- A network failure can delay sync but cannot block local reads/writes or mutate accepted state.
- Gossip carries signed hashes/frontier hints only—never commits, records, keys, capabilities, or blobs.

## Tasks

### Task 1: Convergent Remote Apply Kernel

Add generated fieldwise `IrohRecord` merge adapters and a per-open-database schema registry. Add `accept_remote_commit` as the single validation/materialization entry point. Merge incoming record CRDT states with existing live state, rebuild indexes, and make duplicates idempotent. Test same-record concurrent writes in every receipt order, missing dependencies, wrong author/domain/key, malformed payloads, and no-mutation failures.

### Task 2: M2 Domain Bootstrap and Peer Trust

Add an explicit `DomainSeed` containing domain ID and epoch key, separate per-device endpoint signers, and owner-configured active device membership. Persist trusted device IDs in domain metadata. This is the narrow bootstrap precursor to M3 invitations/capabilities: possession of a key alone does not grant write access, endpoint identity must be trusted, and no key travels through gossip.

### Task 3: Canonical Bounded Sync Frames

Implement `Hello`, `DomainRequest`, `Frontier`, `Need`, `Refs`, `Ack`, `Done`, and typed `Error` frames with strict canonical encoding, version negotiation, nonce replay binding, and hard size/count limits. Add golden bytes, malformed/trailing/oversized rejection, and a deterministic frontier-difference planner.

### Task 4: Immutable Dependency Transfer

Expose the existing iroh-blobs store as `BlobsProtocol`. Resolve referenced commit hashes through iroh-blobs, breadth-first by dependencies, with staging and explicit budgets. Bytes are hash-verified by iroh-blobs and revalidated by the database kernel. Test reorder, duplicate, missing provider, malformed blob, and interrupted retry.

### Task 5: iroh Sync ALPN

Implement a cloneable `ProtocolHandler` for `/iroh-db/sync/1`, bind it beside iroh-blobs in an iroh `Router`, and add an outbound `sync_with` API. Authenticate the QUIC endpoint against configured domain membership and bind every authored commit to that identity. Use minimal/local endpoint presets in integration tests and production-configurable discovery/relay settings.

### Task 6: Gossip Hint Adapter

Register iroh-gossip beside the sync and blob protocols. Derive an epoch-specific unguessable topic, sign bounded announcements, deduplicate/expire/rate-limit them, and trigger ordinary sync on a valid hint. Test that fixtures contain no keys, operations, collection/record IDs, or blob bytes and that dropping every hint still permits explicit reconciliation.

### Task 7: Snapshot Bootstrap and Recovery Matrix

Advertise trusted snapshots when history exceeds a configured threshold, fetch them through iroh-blobs, install through the M1 atomic validator, then reconcile the tail. Add two/three-peer tests for concurrent offline writes, partitions, reordering, duplicate sessions, restart before/after blob fetch and metadata apply, snapshot bootstrap, and eventual byte-identical state roots.

### Task 8: Milestone Gate

Document the public networking API and threat-model changes, run format/strict Clippy/all tests/docs/examples/MSRV, inspect the dependency/protocol split, and record exact evidence in `docs/milestones/M2.md`. Use `superpowers:verification-before-completion`; any convergence, authorization, recovery, or privacy failure keeps M2 open.

## Resolved Decisions

- M2 uses persisted explicit device trust as its authorization root. M3 replaces administration of that set with signed capability/control-chain transitions without changing commit validation order.
- Full commit references are exchanged in bounded pages. Frontier digests are hints only and never proof of completeness.
- Derived record merging is registered by opening the typed collection. A commit for an unknown schema is staged until the application registers its Rust record type.
- Explicit sync is authoritative for repair; gossip only reduces discovery latency.

## Gate

Milestone 2 passes only after deterministic two/three-peer partition tests converge, unauthorized and malformed inputs leave state unchanged, interrupted sessions recover, snapshot+tail equals full replay, and iroh owns every transferred immutable byte.
